What it finds

Four places where development quietly eats your disk

General cleaners look at browser caches and log files. Depflush also reads your projects and your Docker setup, because that is where the big numbers are.

Docker

Build cache and images no container uses are preselected when they can be pulled again from a registry. Images you built yourself, stopped containers and orphaned volumes are listed with a warning and stay unticked.

~/Library/Containers/com.docker.docker/…/Docker.raw

Dependencies

vendor folders next to a composer.lock and node_modules next to a package.json, in projects you haven't changed for 12 months. You choose the threshold. Everything comes back with one command.

$ composer install · npm install

SQL dumps

Dumps over 100 MB are compared by size, then by SHA-256. Only true copies are preselected, and the original always stays. Large dumps that are not duplicates are shown for you to decide.

backup/shopware-db.sql = examples/…/shopware-db.sql

Caches and old IDEs

More than 30 cache locations, plus the caches and logs of JetBrains versions you have already upgraded from. The newest version of each IDE is always kept.

ChromeFirefoxArcSlackVS CodeCursornpmComposerpnpmpipGradleXcodeHomebrewPlaywright

Safety

Nothing moves until you say so

A cleaner that deletes the wrong folder once is never opened again. These rules are built in and cannot be switched off.

Preview first

Every item is listed with its path and size. You confirm the total before anything happens.

Trash by default

Files go to the Trash, so you can put them back. Switch to permanent deletion in Settings when you want the space right away.

Protected folders

Your home folder, Documents, Desktop, Library and your project folders themselves can never be removed.

Open apps are skipped

If Chrome, Slack or any other app is running, its cache is locked until you quit it.

Risky items stay unticked

Containers, volumes, locally built images and plugin dependencies are shown with a warning and are never preselected.

Stays on your Mac

No account, no analytics, no network calls. The scan and the cleanup run entirely on your machine.

Menu bar

FAQ

Questions developers ask

Why is it free?

Depflush is made by Web Loupe, a certified Shopware partner in Berlin. We built it for our own Macs, which fill up with Docker images, client projects and database dumps. If it saves you an afternoon, you can buy us a coffee, and if you ever need help with Shopware, you know where to find us.

Can I read the code?

Yes. Depflush is open source under the GPL-3.0 license. The code is on GitHub, including the exact rules for what it finds and what it never touches. New cache locations are the easiest way to contribute.

Does it send any data?

No. There is no account, no analytics and no crash reporting. The app only reads file sizes on your Mac and talks to your local Docker installation.

I removed something I still need. Now what?

By default everything goes to the Trash, so you can put it back from there. Dependencies come back with composer install or npm install, and images from a registry with docker pull. The History tab shows what was removed and when.

Which folders does it scan for projects?

It looks for common locations such as ~/Sites, ~/Projects, ~/Developer, ~/code and ~/workspace. You can add or remove folders in Settings. A project counts as dormant when none of its own files changed for 12 months; vendor, node_modules, var and .git are ignored for that check.

Why does it need Docker to be running?

Depflush asks Docker itself which images and volumes are in use. That is the only safe way to know. If Docker is stopped, the app offers to start it.

How is this different from CleanMyMac?

General cleaners are built for everyone and mostly look at system caches. Depflush focuses on what developers accumulate: Docker, dependencies of dormant projects, SQL dumps and old IDE versions. It happily runs next to a general cleaner.
